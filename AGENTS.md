# SCANNER CONTROL

Этот файл действует только в репозитории SCANNER CONTROL. Перед изменениями проверь `git status --short --branch`, текущую ветку и локальный diff. Сохраняй чужие правки. За контекстом обращайся к [описанию проекта](docs/PROJECT.md), [архитектуре](docs/ARCHITECTURE.md) и [порядку работы](docs/WORKFLOW.md). [Бэклог](docs/BACKLOG.md) и [журнал решений](docs/DECISIONS.md) обновляй при появлении подтверждённых проблем и принятых решений.

## Рабочий пост

- Скорость выдачи и возврата ТСД — главный приоритет интерфейса. Сохраняй работу сканером и клавиатурой, порядок фокуса, обработку Enter и поток без лишних переходов. Проверяй быструю серию сканов и повторный скан.
- Сохраняй данные и аудит. Состояние, локальный журнал и очередь записываются атомарно. Замена двух устройств — одна операция. Сохраняй версии, идемпотентность, автора офлайн-пакета и совместимость с имеющимися данными. При конфликте сохраняй очередь и сообщай оператору, что требуется сверка.
- Береги IndexedDB, неподтверждённую очередь и историю. Запрещены сброс, очистка, массовые правки и восстановление рабочих данных без отдельного явного разрешения владельца.

## Supabase и публикация

- Работай локально на синтетических данных. Для SQL используй PGlite или отдельно согласованную тестовую базу. При ручном браузерном запуске изолируй адрес рабочей базы до открытия страницы. Автотесты Playwright подставляют API.
- В JavaScript допустим только публичный ключ Supabase. Секреты, токены сессии и реальные складские данные держи вне репозитория, тестов, отчётов и снимков. Сохраняй RLS, узкие права RPC и серверную проверку полномочий. Вход по ID означает заявленную личность.
- Запрещены push, merge, deploy, изменение настроек публикации и действия с рабочей базой Supabase без явного разрешения владельца. Согласуй конкретный diff, целевую ветку, миграции и план отката до публикации.

## Проверка

- Для изменений кода обязательно запусти `npm run check`, `npm test` и `npm run test:browser`. Для исправления дефекта добавь или уточни регрессионную проверку. Для правок только документации проверь пути, команды и diff.
- При изменении кэшируемых ресурсов обнови версию `CACHE` в `sw.js` и проверь загрузку после обновления и офлайн-перезапуск. При изменении SQL проверь ограничения доступа, атомарность, повтор и совместимость очереди.
- В конце перечисли изменённые файлы, проверки и точные причины пропусков. Оставь результат локально для просмотра.
