# Внедрение v12 без входа

По решению владельца терминал работает в общем режиме: без аккаунтов, паролей и ролей. Все, кто имеет доступ к сайту или API, имеют одинаковые возможности. Это не ограничение доступа по сети; при необходимости ограничьте сам сайт и API внешним шлюзом/VPN.

## Публикация

1. Сохранить резервную копию текущего парка, журнала и определений схемы. Не очищать IndexedDB на терминалах.
2. Проверить миграцию `20261113103823_harden_scanner_access.sql` в изолированном PostgreSQL и сценарии браузера.
3. Применить миграцию: чтение остаётся общедоступным, прямые изменения таблиц закрываются. Изменения доступны только через RPC с проверкой версий и обязательным журналом. Старый клиент после этого не сможет отправлять безусловные upsert — обновите открытые вкладки сразу после публикации.
4. Опубликовать весь статический набор одной ревизией. Перезагрузить открытые терминалы. Не удалять локальные данные: очередь старой версии сохраняется для сверки.
5. Проверить сайт, количество устройств, журнал, загрузку изменений, создание/список/скачивание копии. Контрольные изменения выполнять на отдельном тестовом устройстве.
6. Проверить `cron.job` и `cron.job_run_details`: ежедневная копия `sklad-daily-backup` в 01:00 UTC, хранение 30 суток. Копии включают парк и журнал. Публичный запрос создания ограничен одной новой копией за 15 минут.

## Старая офлайн-очередь

Старая очередь не содержит исходной версии и не отправляется вслепую. Скачайте её через диагностику, сверьте с физическим состоянием и облаком. «Согласовать с облаком» переносит рассмотренные пакеты в локальный архив конфликтов и загружает серверное состояние. Новые операции, появившиеся за время подтверждения, сохраняются. Недостающие фактические события оформляются новыми операциями после сверки.

## Восстановление и копии

Восстановление предваряет сравнение изменений и активных выдач. Одна атомарная операция ограничена 500 устройствами. Другие устройства не удаляются; история не заменяется. Списание устройства логическое. Удаление копии из списка лишь скрывает её: содержимое остаётся до окончания срока хранения и доступно по имени через серверную функцию.

Серверные копии находятся в той же базе и не заменяют внешнее резервирование. Перед публикацией сохраняется отдельный JSON-снимок в закрытом Google Drive владельца. Это отдельная копия на момент публикации, а не настроенный ежедневный внешний бэкап. Для постоянного аварийного резервирования требуется внешний планировщик/хранилище или PITR.

## Остальные таблицы и история Git

`warehouse_equipment`, `warehouse_workers`, `warehouse_logs` не используются этим клиентом. Их существующие общие права не изменяются без определения потребителей; в режиме без входа включение RLS с политикой true не ограничит доступ. Реальные устройства удалены из новых исходников. Исторические коммиты и сторонние копии могут содержать прежний слепок; Git history не переписывается при обычной публикации.

При неисправности остановите операции, сохраните очереди и исправьте совместимый клиент. Не возвращайте безусловную запись в таблицы: это снова создаст риск потери изменений другого терминала.
