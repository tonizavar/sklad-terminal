# Архитектура

## Интерфейс и модули

| Узел | Назначение |
| --- | --- |
| `index.html`, `styles.css`, `themes.js` | Одна статическая страница, формы рабочего поста и четыре исходные темы. |
| `app.js`, `workspace.js`, `ui.js` | Выдача, приёмка, замена, ремонт, реестр, фокус, меню и взаимодействие с клавиатурой. |
| `core.js` | Чистые функции валидации, CSV, границ отчёта и сравнения снимков. |
| `connection.js`, `operators.js` | Вход по ID и PIN, локальная сессия, подпись операций, журнал создателя и список постов. |
| `data.js` | IndexedDB v4, локальное состояние, очередь, отправка пакетов, получение снимка и согласование конфликтов. |
| `reports.js`, `backups.js` | Отчёты, серверные снимки, сравнение и восстановление. |
| `sw.js`, `vendor/` | Кэш одной версии статических ресурсов и закреплённый Supabase JS 2.119.0. Запросы к Supabase не кэшируются. |
| `supabase/migrations/`, `tests/` | Версионированный SQL и проверки Node.js, PGlite и Playwright. |

## Путь операции

1. Интерфейс проверяет скан и состояние устройства. `saveDeviceChanges` собирает изменения с исходными версиями и подписывает пакет данными текущей сессии.
2. Одна транзакция IndexedDB сохраняет новое состояние, очередь, локальный журнал и статус последней операции. После отправки пакета статус меняется на подтверждение или необходимость сверки.
3. `syncNow` отправляет операции через `scanner_apply` и подписанные события аудита через `scanner_record_signed_action`. Сервер применяет операции атомарно и распознаёт повтор по идентификатору. При несовпадении версий запись остаётся в очереди для сверки.
4. `scanner_pull` возвращает полный снимок при первом чтении и изменения по курсору при последующих. Списание передаётся как tombstone. Согласование проверяет состояние очереди, сохраняет архив рассмотренных операций и учитывает сканы, добавленные во время подтверждения.

Активный пост запрашивает изменения примерно раз в 5 секунд, фоновый — раз в 30 секунд с учётом ограничений браузера. При возвращении на вкладку или восстановлении сети проверка запускается сразу. Локальный конфликт остаётся в очереди для сверки, а изменения остальных устройств продолжают приходить. Отправка операций с независимыми серийными номерами также продолжается; зависимые пакеты ждут сверки. «Согласование с облаком» архивирует только конфликтные пакеты и сохраняет остальную очередь.

Вкладка проверяет новую версию статики раз в минуту, при возвращении к ней и при восстановлении сети. Service worker активируется после загрузки всего комплекта файлов. Вкладка перезагружается, когда нет незавершённого скана, открытого диалога, сохранения или доступной отмены последней операции. Сессия, журнал и очередь переживают перезагрузку.

## Доступ, хранение и тесты

`scanner_operator_register` позволяет выбрать первый PIN новому сотруднику и активному сотруднику, чья запись создана в прежнем режиме по одному ID. Для создателя и операторов с действующим PIN используется `scanner_operator_login`. Свежая сессия действует 12 часов. `connection.js` добавляет `x-operator-session` при запросе. При сбое связи браузер может продолжить действующую сессию PIN, подтверждённый сервером отзыв её закрывает. Старые сессии по одному ID отзываются, а ранее подписанные операции сохраняют автора и проверяются по времени подписи, как при обычном выходе. Очереди v10/v11 подлежат отдельной сверке.

После успешного получения состояния пост раз в минуту сообщает о связи. Сервер берёт ID поста и сотрудника из действующей сессии и сохраняет своё время. Создатель видит последние 500 постов и может задать им названия в разделе «Операторы».

RPC ограничивают доступ к операциям, журналу и копиям. RLS и SQL-права защищают таблицы. Снимки парка и истории хранятся в той же базе, конфигурация задаёт срок 30 дней. Восстановление проверяет изменения и ограничено 500 устройствами за одну операцию. Успешность расписания в рабочей базе при локальной настройке не проверялась.

Playwright перехватывает запросы к настроенному Supabase и подставляет фикстуры. SQL-тесты выполняются в отдельной PGlite в памяти. Файловый сервер `tests/server.cjs` отдаёт приложение на `127.0.0.1:4173`. Изоляция внешнего API для ручного просмотра описана в [WORKFLOW.md](WORKFLOW.md).
