# Технические решения

Дата ниже обозначает фиксацию решений в документации. Предшествующие решения восстановлены по коду, миграциям и исходным заметкам репозитория.

| Дата фиксации | Решение | Основание и последствия |
| --- | --- | --- |
| 2026-11-14 | Статический клиент без сборки, публикация через GitHub Pages. | Точка входа `index.html`. Supabase JS закреплён в `vendor/`. Статика кэшируется через service worker с версионируемым кэшем. |
| 2026-11-14 | Атомарная модель операций и синхронизация по курсору. | `data.js` записывает состояние, очередь и локальный журнал одной транзакцией. RPC проверяет версии, ведёт серверный аудит и принимает повторный идентификатор идемпотентно. Замена — одна операция с двумя устройствами. |
| 2026-11-14 | Сохранить прежние миграции PIN и подписанные офлайн-пакеты. | SQL миграций `operator_pin_audit` и `self_registration` сохраняет совместимость. Текущий интерфейс использует ID. Автор старых неподписанных записей без доказательств не назначается. |
| 2026-11-14 | Вернуть рабочую компоновку v11 с четырьмя палитрами. | [RESTORE-CLASSIC.md](RESTORE-CLASSIC.md) и `afc50ad`. Выдача, приёмка и реестр остаются на одной странице. |
| 2026-11-14 | В v16 использовать вход по заявленному ID. | Миграция `20261113210902_id_only_operator_sessions.sql` задаёт режим общего поста, автоматическое появление обычного сотрудника и сессию на 12 часов. Подтверждение личности остаётся открытым вопросом бэклога. |
| 2026-11-14 | Проверять изменения изолированно и публиковать только по разрешению владельца. | Проектные правила находятся в корневом [AGENTS.md](../AGENTS.md). PGlite и подставной API Playwright позволяют проверять операции без воздействия на рабочий склад. |
| 2026-11-14 | Обновлять парк по существующему RPC и проверять новые версии сайта из открытой вкладки. | Быстрый опрос по курсору, сохранение конфликтной очереди и смена локальной версии в паузе. Изменений схемы и прав доступа не требуется. |
| 2026-11-14 | Вернуть вход по ID и PIN. Дать выбрать PIN новым сотрудникам и активным сотрудникам, созданным по ID. | Прежние PIN и доступ создателя сохранены. Сессии по одному ID отзываются. Доказательства операций остаются действительными для пакетов, подписанных до отзыва. |
| 2026-11-15 | Изолировать конфликты синхронизации по серийным номерам и согласовывать только конфликтные пакеты. | Конфликт A не должен задерживать независимую операцию B. Зависимые операции A остаются в очереди. Общая сверка больше не снимает корректные неотправленные операции с отправки; поведение закреплено сценариями Playwright на двух постах. |
| 2026-11-15 | Рассчитывать рабочее время по серверу с сохранённой офлайн-поправкой. | Локальные часы постов могут различаться и меняться вручную. `server_time` калибрует просрочку, временные метки, смену и срок сессии без новой миграции. Внутри вкладки используется монотонный ход времени; прошлые записи не исправляются без отдельной сверки. |

Следующую запись дополняй датой, решением, причиной, ссылкой на код или задачу и существенными последствиями.
